# spec-tdd-manager `longrun` flag — design and pre-ship audit record (v1.28.0)

Dates: designed 2026-09-23; audit folded into the final text 2026-09-24. Status: pending maintainer approval → implementation.

## 1. Motivation (field signal)

After v1.27.0's first real run, the maintainer reported (translated from the original): "After real use, the top agent's context size still gets a bit much." That is exactly the trigger condition of the delegation-first knob deferred at design time ("try it this way first; if context really isn't enough, change it later").

The structural cause: the manager strings what used to be four separate sessions (grill, breakdown, audit, driver) into one conversation. The context heavyweights in order: S1 grill's grounding file reads → S3 breakdown recon (duplicating S1's consumption) → S4 audit backflow and the bounce-back loop → S5 (the driver itself is already a lightweight gate; the maintainer ruled it untouched).

## 2. Settled decisions

| Decision | Outcome | Rationale |
|---|---|---|
| Flag name | **`longrun`** (`eco` rejected) | the maintainer pointed out the motive is **keep the top session's context small so it can run longer**, not token economy — this shape RAISES total TOP tokens (the S4 runner is itself a TOP context; boundary duplication). `eco` is defined in loop/dag as token economy; a semantic mismatch. Flag naming by "intent-named plain words" (the v1.26.1 precedent). lean (a family word) / slim were considered; longrun chosen (the motive, named plainly). |
| flag vs default | **flag-first (opt-in)** | crossover: small runs lose on delegation (three dispatch chains + the digest's fixed overhead dominate), big runs win (context pressure dominates); zero real-run data on the delegated path — calibrate first. size-auto (≥N cards) recorded as a future knob. |
| Scope | S1 grounding + S3 drafting + S4 audit-run delegated; **S2 / Gate 2 / S5 / the two gates unchanged** | maintainer ruling: S5 needs no change; S1 included too (delegating the investigation is "also fine"). |
| Runner overflow behavior (per audit (f)) | **STOP and report** (user ruling 2026-09-24) | truncate-never; never digest the trio into the brief (the no-digests rule); the session arbitrates — /clear between stages, or re-run that leg without the flag. Batched auditing was rejected (the v1.14.0 consolidated-attack lesson: batching drops cross-item holes); a size cap was rejected (it excludes the biggest beneficiaries — self-contradictory; recorded as a knob once data exists). |

## 3. Mode design (final after the audit)

`/spec-tdd-manager longrun` — runs without the flag are byte-identical to v1.27.0; the frontmatter description untouched by one letter (the flag never enters routing text).

- **S1 grounding → read-only MID dispatch**. Legal basis (per audit C1's amendment): **task-loop Phase 0's "inventory codebase anchors — a read-only Explore may run the recon" + grill's letter "(or dispatched)"** — collecting grounding facts is not an I19(a) planning object; the delegation is supported by these two existing texts (the original design mis-cited a nonexistent "I19(a) anchor-recon carve-out"; corrected). The output is a **facts digest landed on disk** (same directory as the spec doc): each established fact with `file:line`, relevant symbol/table/config, neighboring conventions, blast-radius surfaces, a **coverage statement (self-reporting what it does NOT cover)**; conclusions and recommendations forbidden (judging is planning leaking downward). Grill works from the digest, keeping **pull rights** (decision-critical specific files may be read directly; an exception, not a bulk-read backdoor) and **follow-up rights** (SendMessage to keep querying the same agent; I18 stands as usual). **Re-entering with the flag + digest already present → reuse, don't re-dispatch, disclosed in one line** (per audit amendment 4: blocks duplicate digest production). The digest path = an S3 brief input, S0 resume material.
- **S3 drafting → TOP-pinned background drafter dispatch** (recorded opt-in #1; **under the flag it supersedes the S3 section's "drafted by this session (planning never sinks)"**, per audit amendment 3; compensation = the TOP pin + the S4 audit already attacking the decomposition dimensions + Gate 2). Brief = the FINAL SPEC path + the digest path + the Phase 0 / Pre-flight 5–6 format + the per-card sniff + the two dag columns; the trio and task docs **written to disk** + a **claims annex** (falsifiable claims with `file:line`). **On completion, stamp "draft complete (YYYY-MM-DD)" in the plan document — no stamp = partial; S0 sends nothing to audit and re-dispatches the drafter** (per a missed audit risk: blocks a half-trio being audited). An adversarial discovery → STOP and report (the report IS the ask; the top relays; a machine's say-so never launches). The session does presentation-level review and amendments only (attributed deltas). **The single-unit route (S3 skipped) does not use this item** (per audit amendment 7).
- **S4 audit run → TOP-pinned background runner dispatch** (recorded opt-in #2; compensation = the TOP pin + the I12 hard carve-out + Gate 2 + **the brief-distiller independence-regression informed-consent line** (audit (d)'s strongest counter-argument): the claims annex is authored by the drafter, raising the auditee's framing power over the audit's questions — bounded by: the checklist dimensions are manager-fixed, the auditor owns its (b)(e)(f) dimensions, and claims were session-authored in v1.27.0 too, so the regression is limited to the distiller grounding). The runner reads `spec-2nd-opinion` / `spec-3rd-opinion`'s SKILL.md from disk by absolute path and **runs it verbatim** (the task-loop handoff pattern; the invoked skills untouched); brief material = the trio + the claims annex + pending decisions, the decomposition dimensions added as in S4. **The findings↔amend↔re-audit loop lives entirely inside the runner**: findings land as files (I19(b)); when the trio needs changes the top only relays paths — a one-line SendMessage to the drafter dispatch (which holds the author's context), the change lands on disk + a delta summary, a one-line call for the runner to re-check; **the single-unit route has no drafter — spec-doc amendments are made by the session (attributed deltas)** (per audit amendment 7). The runner's announce-to-user step degrades to the session's one-line at-dispatch announcement (the I19(e) shape, disclosed; per audit C3 friction 2). **RETURN (per audit amendment 5) = the final plan path + the Gate 2 triple (verdict, folded amendments with attribution, residual risks) + user-owned findings verbatim** (I12: the runner never decides). The close stamp is runner-written; the session verifies the stamp before Gate 2. **A targeted re-audit for a substantive change made AT Gate 2: the session dispatches a fresh scoped auditor directly** (per audit amendment 6; 2nd-opinion's deliberate-fresh letter — the cheapest legal shape). Environment premise `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=3` (the runner dispatches an auditor child internally; the loop's same requirement). **Overflow = STOP and report** (user ruling 2026-09-24): truncate-never; never digest the trio into the brief (the no-digests rule); the session arbitrates — /clear between stages, or re-run that leg without the flag.
- **Silent-death discipline** (all three dispatches alike; **2nd-opinion class: coarse bound + ONE fresh re-dispatch (nothing inherited, disclosed) + stall-report; the runner's bound in tens-of-minutes** — deliberately no loop-class watchdog; the liveness positioning vetoable at maintainer review): dead ≠ no findings.
- **The non-delegable list (always in the session)**: the grill conversation and its recommendations, Gate 1, S2 routing, the relaying of user-owned findings, Gate 2's presentation and approval, the S5 hand-off.
- On resume, re-carry the flag; the digest and findings documents are S0's on-disk material. **Mixed-mode resume (the flag not re-carried) → one-line disclosure, not blocking** (per a missed audit risk).
- **I21 consent mapping (per audit amendment 10)**: the flag's invocation = **recorded consent** for the delegated judgment stages (S3 drafting, S4 arbitration) (LOOP:31's eco shape); the Pre-flight keeps applying to the judgment the session still holds (the grill conversation, Gates 1/2, routing, user-finding relays).
