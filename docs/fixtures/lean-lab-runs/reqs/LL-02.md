# Tiered fee selection — `tierfee.py`

## Background

Treasury charges a flat processing fee on each payout, determined by the
payout's notional amount through a band table. The table is configuration:
the operations team re-tunes band edges and fee figures per market without
code changes, so the module must treat the table purely as data. The same
module is used by the pre-trade cost estimator and by the settlement batch,
which is why the lookup semantics are pinned in a recorded decision below
rather than left to each caller.

## API

```python
tier_fee(notional_cents, tiers) -> int
```

- `notional_cents` — the payout notional as a non-negative integer number of
  cents. A negative value is a contract violation: raise `ValueError`.
- `tiers` — the band table: a list of `(lower_cents, fee_cents)` pairs,
  given in ascending order of `lower_cents`. Both elements of every pair are
  non-negative integers. A table in which the same `lower_cents` appears
  twice is malformed configuration: raise `ValueError`.

Returns the flat fee in integer cents for the matching band.

## Recorded decisions

These were settled with treasury and must not be re-litigated by callers or
by this module:

- **D1 — band matching is inclusive at the lower bound.** A band applies to
  every notional `n` with `lower_cents <= n` (and below the next band's
  lower bound). A notional exactly equal to a band's `lower_cents` is in
  that band, not the one below.
- **D2 — fees are flat per band.** No proration, no rounding of the fee, no
  percentage logic anywhere in this module. The fee for a band is exactly
  its `fee_cents`.

## Rules

The fee for a notional is the `fee_cents` of the band with the greatest
`lower_cents` that still satisfies D1 against that notional. The topmost
band in the table extends upward without limit — there is no upper edge to
outgrow. A notional that falls below the table's first band is below every
band edge; with no band applying, no fee applies.

## Acceptance criteria

1. A notional exactly on a band edge is charged that band's fee (D1).
2. The topmost band matches arbitrarily large notionals.
3. A malformed table (duplicate lower bounds) raises `ValueError`.
4. A negative notional raises `ValueError`.
5. The function reads the table as pure data — no table is hardcoded.
