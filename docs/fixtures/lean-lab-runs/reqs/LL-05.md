# Instrument code normalization — `codes.py`

## Background

Instrument codes arrive from three upstream systems with three different
formatting conventions. Downstream matching joins on the normalized form,
so normalization must be total and deterministic: the same input always
yields the same code, and two codes normalize equal exactly when the systems
mean the same instrument. This module is that normalization, as one pure
function.

## API

```python
normalize_code(s) -> str
```

`s` is the raw code string. Returns the normalized code. Contract
violations raise `ValueError`.

## Normalization rules

1. Trim: strip leading and trailing whitespace from the raw string.
2. Separator collapse: every maximal run of separator characters — each of
   hyphen `-`, underscore `_`, and space — is replaced by a single hyphen.
   A run may MIX the separator characters (e.g. `"_- "` is one run) and
   still collapses to one hyphen.
3. Case: lowercase letters are folded to uppercase. Digits are kept as-is.
4. Alphabet check: after trimming, every character must be an ASCII letter,
   a digit, or a separator character. Any other character (punctuation,
   symbols, non-ASCII letters) is a contract violation: raise `ValueError`.
5. Emptiness: a string that is empty, or contains only separator or
   whitespace characters, has no code in it: raise `ValueError`.

The checks apply in the order given: a string that fails the alphabet check
raises even if it would also be empty after collapse.

## Acceptance criteria

1. Mixed separator runs collapse to exactly one hyphen.
2. Lowercase input folds to uppercase; digits pass through.
3. Any character outside the alphabet raises `ValueError`.
4. Empty or separator-only input raises `ValueError`.
5. Normalization is idempotent: normalizing an already-normalized code
   returns it unchanged.
