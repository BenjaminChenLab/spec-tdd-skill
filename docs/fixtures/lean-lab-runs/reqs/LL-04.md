# Currency conversion service — `fx.py`

## Background

Position revaluation converts every book entry into the desk's base
currency. Conversion used to be a private helper inside the positions
module; risk reporting now needs the same conversion, so it is being
extracted into a dedicated service module. The tree you are working in
already has the positions module rewired to call the new service — the
service itself is what does not exist yet, and your acceptance suite is
written against it before any implementation exists.

## API

```python
convert(amount_cents, pair, rates) -> int
```

- `amount_cents` — the amount to convert, as an integer number of cents.
- `pair` — a currency pair tuple `(from_ccy, to_ccy)`, e.g.
  `('USD', 'EUR')`.
- `rates` — the rate table: a dict mapping `(from_ccy, to_ccy)` tuples to
  positive float rates (1 unit of `from` costs `rate` units of `to`).

Returns the converted amount in integer cents.

## Rules

**Direct hit.** When `rates` contains `pair` itself, the result is
`amount_cents * rate`, rounded to the nearest whole cent, halfway cases
rounding up (`150.5` goes to `151`, not `150`).

**Inverse fallback.** When `pair` is absent but the reversed pair
`(to_ccy, from_ccy)` is present with rate `r`, the conversion goes through
the inverse rate: the result is `amount_cents / r`, rounded the same way —
nearest whole cent, halfway up.

**Unknown pair.** When neither the pair nor its reverse is in the table,
the conversion cannot be performed honestly: raise `ValueError`. Silently
returning the input amount is forbidden — an unconverted amount in the
books is worse than a loud failure.

## Integration notes

The positions module (in this tree) calls the service once per book entry,
across an entire book, reusing one rate table for the whole batch. Read
`positions.py` before settling the service's contract — the callers show
the shapes that actually arrive, including how the desk represents
direction.

The batch path is latency-sensitive: keep the conversion a straight pure
computation over its arguments — no caching layers, no global state.

## Acceptance criteria

1. Direct-pair conversion rounds half up at the whole-cent boundary.
2. A reversed pair converts through the inverse rate with the same rounding.
3. An unknown pair (and an unknown reversed pair) raises `ValueError`.
4. The function is pure — identical calls return identical results.
