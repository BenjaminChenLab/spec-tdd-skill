# Recovery and resume — spec-tdd-supervisor (progressive reference)

Part of `spec-tdd-supervisor` (v1.36.0 progressive split — the SKILL.md's flow pointers load this file on demand). **Read it at any breakpoint: a soft-wedge or freeze diagnosis, the first post-429 successful turn, an announced absence (going-dark), or a session break with the unit half-finished.** A healthy uninterrupted run never reads it. This skill stays self-contained: everything below belongs to this skill, split out only for load-on-demand.

---

**Soft-wedge recovery.** Reset moment known AND still future — read the current wall clock first (a past reset = quota back: resume now, nothing to schedule; field 2026-10-21: a revival scheduled a point 5h45m past) → schedule a reset+15 nudge (SendMessage wake + convergence instruction); waking grace ≈10–15 min (children before the parent, an n=1 buffer); reset moment unknown → nudge immediately (costs nothing even if undeliverable) + one grace cycle; still frozen → the joint surgery of the three-state judgment's (b), **never an unbounded wait**. **Waking ≠ done**: the first waking round delivers the entire backlog in order (including hours-old policy — the top immediately follows with a confirmation / rescind), and the final report is still some distance away. **A delivered resume silent for minutes is slow-start, not death** — judge only after the grace expires (field: ~9-min silence misread as death; the agent woke and converged).

**Freeze auto-recovery (freeze SOP).** The main session and level-1 may share a pool — during a 429 freeze the top cannot act either; the only levers inside the window are the ring's recurring retries (each in-window landing dies free; the first post-recovery landing wins — the recurring substrate, v1.32.1) and manual user messages. **The first successful turn (from any source: a ring landing / a manual user message / quota trickle) must do three things**: (i) record the 429 event, pool, reset moment, and freeze start into `RUN-STATE.md` (transcript error lines get eaten by compaction — the file is the re-arm base); (ii) schedule the reset+15 insurance point — only if the named reset is still future (current wall clock read first; past → collect-and-resume now; a found schedule's CREATION time checked against now — field 2026-10-21) — durable when that future reset falls outside the session's expected attended life (single fire, named moment, self-retiring; a missed durable one-shot catch-up-fires at the next launch — field 2026-10-06: the session-only shape never fired overnight); (iii) disclose the freeze. **That turn collects before judging**: first digest the backlog from the freeze window (task notifications, agent states, RUN-STATE reconciliation) — a level-1 that finished during the freeze presents as a "total freeze" shape; check for closure before running the three states, or you'll wrongfully kill your own healthy card; a known freeze window is **deducted** from the output-age and budget readings (the freeze is the top's account, not the agent's — a mechanical over-budget kill here is a wrongful kill). **Post-first-429 dispatch discipline**: subsequent dispatches must not silently land in that pool — a known different-pool model satisfying the MID pin may be named, otherwise pause until the named reset.

**Unattended window (going-dark).** The user announces leaving/sleeping/going offline with the unit in flight → read `{family root}/skills/GOING-DARK.md` and execute it NOW (one batched pre-approval ask — expected return, recovery actions, tier ceiling, open decisions, commit handling per this skill's no-commit close — plus substrate choice and optional OS-level fallback arming; tier pins stay MID). If the file is unreadable, still run the gate: batch-ask those items once and disclose that the protocol file was unread.

## Half-finished-work resume (after a session break)

Session break / context corruption, the run stopped mid-way. This skill has no board — **the trace base = `RUN-STATE.md` + `REPORT.md` + git**:

1. **Inventory first, never rewrite** — read `RUN-STATE.md` (in-flight facts: unit, dispatch moment, budget, commit mode) + `git status` / `diff --stat` against the requirement doc, path-level mapping to judge which changes are legitimate half-done work; if level-1 already wrote `REPORT.md`, recover the numbers and hashes from it — never dig through a dead conversation.
2. **Level-1 still alive → prefer SendMessage to resume the same agent** (a background dispatch keeps its full context; the existing 429-break rule: agent dead, session alive → SendMessage resumes). The dead one is the nested implementer → the recovered level-1 re-dispatches a continuation implementer itself, sunk one level down.
3. **Re-dispatch a continuation level-1 (keep-don't-rewrite)** — attach the inventory result (diff file list + scope mapping) + "keep existing legitimate changes, fill only the gaps, never rewrite" + read `.spec-tdd/POLICY-<unit>.md` first (the cold-start policy source) + carry USER-FLAGGED GAPS. Budget re-granted by remaining scope (inheriting a burned-through budget = an instant kill).
4. **Re-arm — re-create + verify the recurring ring at the resumed session's first dispatch** (the old schedule was session-scoped and died with the session; identity/cadence from RUN-STATE's disclosure row); RUN-STATE gets the breakpoint record (break moment, re-dispatch generation).
5. **Interrupted at the final-audit stage** — auditor in flight → same rule, SendMessage-resume preferred (its context holds the deep-review memory); `FINAL-AUDIT.md` already written (findings complete or partial) → recover from the file, never re-dispatch a completed review; audit not yet dispatched → the new session simply dispatches it (objective items re-run — the machinery is cheap).
