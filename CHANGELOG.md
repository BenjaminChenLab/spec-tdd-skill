## [1.29.0] - 2026-09-24

### Added
- **`spec-tdd-quickfix` — the live-testing quick-fix floor, fourteenth skill** (maintainer's ask, translated from the original: "The user is testing and will keep finding small issues that need a quick fix; no time to test carefully right now, and these small fixes — changing some text and the like — don't need careful testing. Shape: the user live-tests and streams small fix requests; the orchestrator gives a **one-sentence fix plan** (file + intent — no ticket doc, no Gate 2; the user's go is the only gate, riding their global never-code-before-approval rule) → dispatches **ONE MID subagent** (model stated per I19(a)) behind a **scope fence** with pinned decisions and report-don't-guess → **tiered verification floor**: text/config change = compile + the orchestrator's full diff read; logic touch = + scoped test re-run after agents are down → final report **discloses the substitution** (the orchestrator's diff read + the user's live testing stood in for the family's audit machinery — never passed off as a verified run). Escape valve: a fix that grows mid-flight (structural, blast-radius, needs test design) leaves the lane for lite or above. Parallel only when streamed fixes have disjoint file sets; shared file ≤2 editors with re-Read-before-every-edit; same region or un-landed dependency → queue. Standing discipline inherited from the W32–W36 field run: NO agent git (orchestrator commits per explicit go, explicit paths, never `-A`), gradle lock = wait never kill daemons, build output redirected to file (pipes swallow exit codes), foreign compile failure = wait 90s×2 then report honestly. **Origin**: another session had recorded the 2026-09-24 W32–W36 dtms-core run as a heavyweight `spec-tdd-batch` draft (ticket docs, parallel file matrix, per-card QA); the maintainer rejected the weight ("I am not insist to have this skill… just need a quick fixing flow") — the batch folder was deleted and the flow rewritten as this floor tier, keeping only the field-discipline lines.
